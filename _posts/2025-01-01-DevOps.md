## <span style="color: blue;">DevOps 01: What is DevOps</span>

### <span style="color: blue;">Why we need DevOps?</span>

Traditional software development is originally processed by two teams:
1. Development Team
    Development plans are designed and built from scratch by the development team, The system needs to be constantly updated and iterated
2. Operation Team
    The operation team tests the code of the development team and deploys it, they are responsible for the stability and security of the software system.
<!--more-->
Development and operations teams often work in silos with conflicting goals: **developers focus on rapid feature delivery, while operations prioritize stability and uptime.**

Two teams with different goals need to collaborate and implement one software --> Culture Barriers, as the development team works in development environment, the operation team need to deploy the code in production environment. --> longer development life cycle, inefficiencies in delivering software. 



### <span style="color: blue;">Solution: DevOps</span>

![devops]({{site.baseurl}}/assets/img/devopscycle.PNG)

> We promote agile development. DevOps integrates the development team and operation team into one team for delivering software, fosters better collaboration, automation, and a culture of continuous improvement. DevOps stands for Development & Operations

**The Cornerstone of the DevOps is to simplfy and automate the communication between Dev & Ops teams, making the software development more agile**

> Different Phase of DevOps:

1. PLAN: Dev team makes a develop plan according to the customers' requirements.
2. CODE: Coding based on the plan and store different versions of the code in a repository.
3. BUILD: After the coding is complete, the code needs to be built and executed.
4. TEST: Test the code and find BUGs and Errors.
5. DEPLOY: After manual test and automated test, handle the code to Ops team for further deployment.
6. OPERATE: Ops team deploys the software into the production environment.
7. MONITOR: After the code is deployed, monitor continuously the product.
8. INTEGRATE: Collect all the feedback from previous phase and report it to the Dev teams, so that they can start a new iteration from PLAN phase

The core of DevOps is CI/CD pipeline, resp. Continuous Integration and Continuous Delivery.

> **Definition of DevOps:**
> **DevOps emphasizes efficient communication and collaboration between teams through automation tools to achieve effective management of the software lifecycle, enabling faster and more frequent delivery of stable software.**
